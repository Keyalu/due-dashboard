错题 017｜RIP坏消息传得慢-计数到无穷-多邻居取最小

📅 2026-09-20 · 知识点：RIP坏消息传得慢-计数到无穷-多邻居取最小
错误类型：概念不清状态：待复习章节：CN/网络层

一、题目原图

题目

【2016 题 37 · RIP 坏消息传得慢】R1、R2、R3 采用 RIP 协议交换路由信息，且均已收敛。若 R3 检测到网络 201.1.2.0/25 不可达，并向 R2 通告一次新的距离向量，则 R2 更新后其到达该网络的距离是（　）。
A. 2　　B. 3　　C. 16　　D. 17

拓扑：R1—R2、R1—R3、R2—R3 两两直连；201.1.2.0/25 直连在 R3 上。收敛时 R1 到该网络距离为 2（下一跳 R3）。

核心结论

R2 收到 R3 的"16"不会直接变 16，而是去问另一个邻居 R1：R1 还不知道网断了，仍报距离 2，所以 R2 经 R1 走的距离 = 2+1 = 3。这就是 RIP"坏消息传得慢（计数到无穷）"的开端。

推导过程

① 收敛时（R3 直连度量 = 1）：
  R3 → 网络：距离 1（直连）
  R1 → 网络：经 R3，距离 1+1 = 2（下一跳 R3）
  R2 → 网络：经 R3，距离 1+1 = 2（下一跳 R3）

② R3 检测到网络断了：把自己到该网络的距离改成 16，通告给 R2。

③ R2 收到 <网络, 16>：它有两个邻居，不能只看 R3——
  · 经 R3：16（不可达）
  · 经 R1：R1 还不知道网断了，R1 报距离 2 → R2 经 R1 = 2+1 = 3
  比较取小：3 < 16 → R2 改走 R1，距离 = 3。

为什么这是个坑

  • 选 C（16）：只看到 R3 通告 16，忘了 R2 还有另一个邻居 R1 可以选。
  • 选 D（17）：机械地把 16+1 算一跳，没考虑 R2 会比较所有邻居通告、选最小距离。
  • 本质：R2 以为"绕 R1 还能到"，但 R1 的下一跳也是 R3——这条路实际是 R2→R1→R3→死路。R2 和 R1 接下来会互相以为对方能到，距离从 2→3→4→… 慢慢爬到 16 才都认定不可达。

正确解法要点

RIP 更新规则：对每个邻居发来的距离 d，计算"我经它到目的 = d+1"，所有邻居里取最小；只有当最小者 = 16（所有邻居都报 16）时，自己才把该目的标记为不可达。
本题 R2 的邻居 R1 报 2 → 经 R1 = 3，所以暂时还可达。

同类易错提醒

  1. RIP 距离矢量更新是"遍历所有邻居取最小"，不是只看断网那台邻居。
  2. "计数到无穷"（坏消息传得慢）：网络故障后距离要一跳一跳涨到 16 才收敛，慢；对应解决方法有水平分割、毒性逆转、触发更新、抑制时间。
  3. 对比上一题（016）：R3 通告 16 给 R2，R2 如果只有 R3 一个邻居，才会直接变 16；本题 R2 多了 R1 这个邻居，所以变 3。两题放一起对比着记。
